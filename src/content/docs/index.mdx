## Every seat keeps itself going

A Claude Code session fills its context and slows down. A seat writes a recap
before that happens, clears, and its successor starts on the recap's next
step. Workers do it, and so does the master that routes their work, so nothing
waits on one long conversation.

## One key away

Press `Ctrl+\` inside any seat and the seat view opens over Claude: this
seat's state, who its master is, every other seat, and the work in flight.
Arm, clear, message another seat or leave, each with one key. `q` returns to
Claude where you left it.

<SeatView />

## The state lives in a cairn, not in the conversation

A conversation is working memory: fast, limited, and safe to throw away once
nothing important lives only there. The cairn is one directory that holds the
rest on disk: each seat's recap, each project's routing skill and the files to
read first, the open work, and the log of what every seat did. That is why a
clear loses nothing.

Onboarding a repository is one line inside a seat, and Claude writes the
project's routing skill from its own docs.

```text
/supervise init ~/code/atlas
```
